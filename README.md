# Программирование на Python

Общий репозиторий курса ИТМО. Здесь публикуются правила, материалы лекций и инструкция по сдаче заданий. Сами задания и ваши решения живут в личном приватном репозитории.

## Как всё устроено

1. Вы заполняете форму регистрации и получаете приглашение в приватный репозиторий `itmo-python-programming/student-<ваш GitHub-логин>`.
2. Преподаватель публикует задачи прямо в этот репозиторий: каждая задача — отдельная папка, например `01_Basic/01_Hello_World/`. Внутри `README.md` с условием, файл для решения и публичные тесты `test_public.py`.
3. Решение сдаётся пушем в ветку `main`. После пуша GitHub Actions запускает тесты, результат виден во вкладке Actions репозитория и приходит в Telegram.
4. Решения с зелёными тестами попадают на взаимное ревью: вы проверяете чужие решения, вас проверяют другие. Ревью анонимное и проходит на сайте курса, ссылки приходят от бота.

## Первые шаги

### 1. Примите приглашение

Письмо от GitHub придёт на почту аккаунта. Также приглашение видно на странице https://github.com/itmo-python-programming — примите его, иначе репозиторий будет недоступен.

### 2. Привяжите Telegram

Откройте ссылку вида `t.me/<бот>?start=КОД`, которую выдал преподаватель, и нажмите Start. Бот будет присылать новые задачи, дедлайны, результаты тестов и назначения на ревью.

Команды бота: `/tasks` — ваши задачи и статусы, `/reviews` — что нужно проверить, `/login` — ссылка для входа на сайт, `/me` — профиль.

### 3. Склонируйте репозиторий

```bash
git clone git@github.com:itmo-python-programming/student-<логин>.git
cd student-<логин>
```

Если работаете по HTTPS, понадобится personal access token вместо пароля. Проще один раз настроить SSH-ключ: https://docs.github.com/en/authentication/connecting-to-github-with-ssh

### 4. Подготовьте окружение

Нужен Python 3.13 или новее.

```bash
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install pytest pytest-timeout
```

## Как решать задачу

Откройте `README.md` задачи, реализуйте функцию в указанном файле. Меняйте только файлы внутри папки задачи. Файл с тестами `test_public.py` менять не нужно: на проверке он всё равно будет заменён.

Запустите тесты локально:

```bash
python -m pytest 01_Basic/01_Hello_World
```

Когда всё зелёное, закоммитьте и отправьте:

```bash
git add 01_Basic/01_Hello_World
git commit -m "Solve 01_Basic/01_Hello_World"
git push
```

Через минуту во вкладке Actions появится результат прогона. Красный крестик — откройте job с именем задачи, там лог pytest. Можно пушить сколько угодно раз, засчитывается последний коммит до дедлайна.

### Когда преподаватель добавляет новые задачи

Новые задачи появляются в репозитории коммитом `Publish …`. Перед началом работы забирайте изменения:

```bash
git pull --rebase
```

Если вы редактировали только файлы внутри своих задач, конфликтов не будет.

## Взаимное ревью

После дедлайна (или сразу после зелёных тестов, зависит от задачи) вам назначаются два чужих решения этой же задачи. Бот пришлёт ссылку, срок обычно три дня.

На странице ревью:

- слева список файлов, в центре код с номерами строк, справа условие задачи;
- нажмите «+» рядом с номером строки, чтобы оставить комментарий к ней;
- в блоке «Обсуждение» можно оставить общий комментарий;
- в конце выберите вердикт: «Одобрить» или «Нужны правки», при желании напишите итог и нажмите «Завершить ревью».

Автор увидит ваши комментарии только после завершения. Ваше имя автору не показывается, имя автора не показывается вам. Отвечать на комментарии к вашему решению можно на той же странице.

Что смотреть в чужом коде: корректность на граничных случаях, читаемость и имена, лишнюю сложность, соответствие условию. Пишите так, как хотели бы, чтобы написали вам.

## Сайт курса

Личный кабинет: ссылка для входа приходит по команде `/login` в боте. В кабинете видны все ваши задачи, статусы тестов, полученные ревью и очередь ревью, которые нужно сделать.

## Правила

- Решение должно быть вашим. Обсуждать идеи можно, копировать код нельзя.
- ИИ использовать можно, но в домашних заданиях я бы советовал полностью обходиться без него: готовое решение не закрепляет навык.
- Дедлайны указаны в кабинете и в сообщениях бота. Сдача после дедлайна отмечается отдельно.
